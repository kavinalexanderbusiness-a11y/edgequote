## Existing contract retained

Use the exact existing service-only pilot_quote_acceptance_preview/commit/reconcile signatures. Owner authority comes from fresh verified getUser in the server adapter; browser never submits owner identity as authority. Portal authority is exactly the request's existing token, resolved and locked again inside SQL. Exactly one authority mode, no fallback. Private rows/token/terms classification/no-charge attribution remain outside public previews and diagnostics.

The complete expected object is immutable native output: version, quoteId, opaque previewRevision, priorAcceptanceId/Seq and offered.public plus opaque authorityFence. Do not recompute its hash in JavaScript; numeric JSON roundtrips already have native regression coverage. All exact child fields/ordering, selected IDs, raw nulls and text survive. Validate a bounded plain-JSON copy with explicit key/type/unique-ID/order/membership checks. Missing arrays, wrong values or failed reads refuse, never become an empty collection or cached success.

Native reconciliation deliberately ALWAYS returns unknown in current reviewed SQL. No positive reconciliation path will be invented. One immediate read-only reconciliation at most per uncertain write; no automatic write replay or fresh preview/rebase after confirmation. A later full-history reconciliation policy requires a separate review.

## Runtime and HTTP surfaces (dormant)

Add browser-safe strict request/preview/receipt validators and a server-only adapter using the existing bounded same-origin JSON policy (200,000-byte entire request cap, no-store replies, bounded cancellation-aware reads). No route files or schema changes.

Preview request exactly the reviewed shape: {version:1,quoteId,optionId:null|string,portalToken?:string}. Commit adds {expected,addonIds,reason:null|string,note:null|string,termsAck:boolean,clientOperationId}. Read-only reconciliation uses that same captured commit request; adapter forwards only native reconciliation arguments. Owner reason is one canonical ON_BEHALF_REASONS value, optional note follows existing trimming behavior and is frozen before dispatch. Portal forbids reason/note. Owner termsAck records explicit owner attestation semantics, never masquerades as a customer portal tick.

Preview response remains {code:'preview',expected}. Enforce its full response200,000-byte cap separately, and reserve an exact future full commit using ACTUAL token/expected/addon IDs, a valid36-character client operation UUID, the longest canonical owner reason (text_message; portal null), note:null and termsAck:false. The latter two exceed empty-string/true JSON widths. The required commit must fit200,000 UTF-8 bytes without truncation. Optional note may use remaining capacity; validate the FINAL complete request before dispatch, and explicitly refuse oversize rather than truncating it or claiming any arbitrary note fits. Native portal token limit10,000 UTF-8 bytes and combined owner reason/note limit200,000 UTF-8 bytes remain; the total request cap is tighter. Reasons use the canonical enum only, with no invented default. Native accepted_amount must be finite/non-null; nullable raw initial_price remains distinct from zero or declared no-charge in display.

HTTP commit reply wraps the strictly checked native receipt in {code:'accepted',clientOperationId,previewRevision,receipt}. A receipt must match quote, accepted amount, chosen option, exact addon IDs, prior acceptance and successor sequence, mode kind/source, verified owner actor when in owner mode, and valid actor/customer/ledger IDs and fingerprints. Native receipt already performs owner/customer/actor consistency checks; do not accept browser ID as authority or invent absent public customer IDs. Unexpected/malformed/transport-failed responses after dispatch are unknown, not proof of rollback.

Wire refusals are explicit: preview failure is {code:'refused',reason}. A parsed commit's known pre-DML refusal is {code:'refused',clientOperationId,previewRevision,reason}; unknown write/reconciliation is {code:'unknown',clientOperationId,previewRevision}. Native pre-DML allowlist is exactly invalid_request, unsupported_isolation, not_found, not_eligible, invalid_choice, quote_changed. An exception or malformed native reply after commit invocation becomes unknown. HTTP boundary failures before native invocation may use method_not_allowed, forbidden_origin, invalid_request, request_too_large, unauthenticated or unavailable; echo correlation only after the request has parsed and bound it. An uncorrelated response after browser dispatch is not accepted as a bound known refusal. Read-only preview failures may say unavailable without implying business state. Reconciliation never returns a positive accepted receipt under this contract. Preserve specific native refusal reasons in client-facing explanations, without forwarding raw exception text or private metadata.

Store methods accept scoped owner-or-token arguments and AbortSignal. Service-role credentials stay in the injected server store, never browser. Tests use synthetic verified auth and the existing marked disposable native SQL transport. Real HTTP route/Auth/PostgREST activation remains a later gate.

## Actual caller integration

Add an optional capability to actual PortalClient and RecordAcceptanceDialog; absent capability retains current production behavior and existing verification controls. The shared browser controller owns preview/confirm/dispatch/reconcile lifetime, with a synchronous reentrancy guard spanning the whole operation. Actual caller controls and actual modal rendering are exercised; do not replace them with copied event handlers.

Portal: existing Billing/Home accept entrypoints provide only quote/option launch hints. Old card termsAck, cached amounts and load() results cannot authorize confirmation. A new native preview provides the entire displayed document; terms assent starts false and uses canonical TERMS_ACK_LABEL/termsRequired. Token-prop changes and unmount invalidate every old asynchronous result and callback. Each operation captures exact token and controller generation; never store token/expected data in browser persistence or log it.

Owner: capture verified CacheOwner lease at opening and check it through every read/confirmation/result callback. Quote/open generations are explicit. Parent quote/option/terms/customer props cannot replace the displayed snapshot or retain the previous attestation after a new preview. Reason/note/option controls are disabled while submitting. onRecorded only runs after a bound direct receipt while the originating owner, quote and dialog generation remain current. onClose may follow explicit dismissal (Cancel/Done/close); it never means success or rollback and never removes pending/unknown protection. A stale asynchronous result cannot close or update a newer dialog. A confirmed direct receipt may notify the originating live parent but does not automatically substitute a newly fetched displayed document.

SQL preview requires an option for a quote offering alternatives. Existing owner/portal option controls remain preliminary choices; their IDs trigger a new preview, never imply authorization or silently default to recommended. If a stale option is absent, refuse with the stated invalid-choice reason. During a choice reload hide/disable confirmation and reset assent/reason for the next displayed version. Do not display old option prices/terms as the confirmation while loading or failed.

Both confirmations render only immutable offered.public: customer/quote/address, chosen option and description, service scope and ordered commercial lines, included extra names/prices with exact IDs internally, full public notes/terms, native accepted_amount, validity, recurrence per-visit alternatives and applicable GST/deposit timing. Use existing formatCurrency, requiredDeposit, paymentTiming and approvalTimingLine for formatting/timing; never recompute the accepted amount or claim an option/extra not included. Nonchosen options/addons are explicitly excluded; cancel to change add-on selection through its separate workflow. No public internal notes/credentials/no-charge attribution.

The confirmation button is the explicit consent to the itemized document (and owner reason/attestation). Immediately before sending, check originating lifetime and the bound validity date with existing displayQuoteStatus/localTodayISO policy. Repeat expiry check without introducing a new server timezone policy. Capture an immutable complete request once; preserve exact expected and IDs through the awaited write. No fresh document read at this point. Success uses validated returned amount/identity, not local quote status or cached dialog totals. Keep the accepted document visible with a clear recorded state; do not replace it from a late refresh.

Install a per-authority/quote in-memory pending tombstone synchronously BEFORE invoking the write. Pending/unknown blocks ALL further acceptance commits and new previews intended to commit for the same authority/quote, regardless of a new operation ID, close/reopen, or remounted child-dialog generation. Keep the registry outside those generations. Retain the entry through thrown/late/aborted transport responses; unknown reconciliation cannot clear it. Returning to a previously used owner/token cannot evade its unresolved entry. A different authority never sees that document or inherits its request. Tokens remain memory/request-local, never persisted or logged. Explicit dismissal retains this protection and makes no rollback claim. Terminal states cannot borrow a newer lifecycle to fire callbacks. Browser reload recovery or durable acceptance journals remain separate scope, not silently promised.

Automatic owner capability or lease recovery while a dialog remains open restores a known accepted copy and receipt without a new preview or success callback. Only a new explicit parent opening may request another version after a resolved receipt. Opening intent is distinct from authority/callback epochs; changing authority while awaiting availability does not manufacture a new user action.

## Proof and release boundary

Implementation clarifications reviewed against existing native behavior: an unpriced chosen base (null or nonpositive without a no-charge declaration) is not displayed as a free acceptance, even when extras/travel make the offered total positive. Use the existing native base check without recomputing accepted_amount. A true no-charge declaration with positive extras still displays the offered positive total. A direct accepted receipt resolves its pending entry: only an explicit later opening may request a fresh preview, with a new operation and no old callback replay. Pending/unknown entries remain non-clearable across openings. An already-open second review that encounters another dispatch says its own review was not sent and directs explicit reopen to the submitted copy; it never relabels its different preview as the uncertain submitted document.

Source/behavior review both actual callers independently. Separate strict synthetic full-component suite imports PortalClient, actual Billing/Home controls, RecordAcceptanceDialog/Modal/CacheOwner and dormant Save editor; forbid legacy acceptance calls and unrelated writes. Cover exact document/addons/terms, stale/failed/missing reads, choice changes, owner/token/unmount transitions, double input, explicit reason, amount receipts, zero/declared-no-charge wording, expiry, corrupt receipt, delayed response and one unknown reconciliation with no replay.

Use current native Save-versus-portal/owner acceptance ordering cases and new adapter cases; carry sanitized native response fixtures/hashes into mounted checks where practical. Explicitly distinguish bridged native response fixtures from a live browser-to-PostgREST/durable outer-COMMIT flow. No heavy local build/native PostgreSQL; scoped compiler/lint/browser work only, cloud heavy CI. Exact committed source/runner measurements and artifact audits before PASS claims; preserve failed receipts.

Legacy signatures close only in the same eventual reviewed S106 schema-first release as all versioned callers; never activate one side now. Real auxiliary loading, authenticated full-app/native durable transaction proof and S106 landing remain later gates. Keep unified-workspace/PR125 follow-on queued.
